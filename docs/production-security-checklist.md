# Production Security Checklist

Use this checklist before launching Zenna Craft in production.

## Environment

- Set `APP_ENV=production`.
- Set `APP_DEBUG=false`.
- Use a strong `APP_KEY` generated by Laravel.
- Keep `.env` outside public web access.
- Rotate secrets after staging or vendor handoff.

## HTTPS and Sessions

- Serve the storefront and Studio over HTTPS.
- Set `APP_URL` to the production HTTPS URL.
- Enable secure cookies in production with `SESSION_SECURE_COOKIE=true`.
- Keep session cookies HTTP only.
- Keep SameSite configured for session cookies.

## Authentication and RBAC

- Keep Studio on `/studio`; never expose `/admin`.
- Require staff authentication for every Studio route.
- Review owner, manager, staff, finance, marketing, and operational roles before launch.
- Ensure finance, marketing, diagnostics, settings, staff, backup, and audit permissions are restricted.
- Disable or remove unused staff accounts.

## Rate Limiting

- Keep named limiters enabled for staff login, OTP request/verify, checkout, tracking lookup, behavior events, cart mutations, coupon attempts, and review submission.
- Monitor failed login attempts and OTP abuse.
- Avoid raising limits unless real traffic requires it.

## Uploads

- Allow only image uploads needed by the storefront.
- Keep SVG uploads blocked.
- Keep file size limits conservative.
- Validate MIME type, extension, filename, and readable image bytes.
- Store generated filenames rather than user-provided filenames.

## Data Privacy

- Do not log raw phone numbers, emails, addresses, IP addresses, or full user agents in diagnostics or audit metadata.
- Keep behavior events hashed and sanitized.
- Keep review moderation notes private to Studio.
- Keep fraud, verification, and staff notes out of public views.

## Signed and Customer Routes

- Keep invoice routes signed.
- Keep customer order, tracking, invoice, and review access scoped to the authenticated customer.
- Keep public tracking protected by matching order number and phone.

## Headers

- Keep secure headers middleware enabled.
- Use `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`, and `Permissions-Policy`.
- Enable HSTS only after HTTPS is ready.
- Prepare a Content Security Policy after inventorying storefront scripts and inline styles.

## Queue, Cache, and Scheduler

- Run the two queue worker processes in production — a dedicated `otp`-only
  worker plus a `transactional,bulk` worker. Never a single worker sharing
  the `otp` queue with anything else. See `docs/queue-setup.md`.
- Run `php artisan queue:restart` after every deploy so workers pick up new
  code.
- Check `/studio/system-diagnostics` Queue Health (OTP queue health and
  worker heartbeat) after every deploy and periodically in production.
- Run Laravel scheduler through cron or a process supervisor.
- Keep cache and view cache warm after deployment.
- Do not expose public cache-clearing routes.

## Backup and Recovery

- Configure backup storage before launch.
- Validate at least one backup restore path.
- Restrict backup management to owner/manager roles.
- Keep backup disks and credentials private.

## Demo Data

- Do not run `DemoQaSeeder` automatically in production.
- Check diagnostics for demo-prefixed records before launch.
- Clean only demo-prefixed records when leaving QA or staging.
